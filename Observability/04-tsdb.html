How a time series database stores data

Why can Prometheus hold millions of samples in a few bytes each? Because time series data is very predictable, and a TSDB exploits that.

Explain pull (scrape) vs push, describe the write path (memory → WAL → blocks), and compute delta-of-delta compression by hand.

Why not just use a normal database?

Metrics workloads are unusual: writes are constant, append-only and ordered by time; you almost never update old data; reads ask for a time range of one or a few series; and old data gets less valuable. A time series database (TSDB) such as Prometheus's built-in TSDB, VictoriaMetrics, InfluxDB or Mimir is built for exactly that.

Getting data in: scrape (pull) vs push

Pull: Prometheus visits each app's /metrics page every scrape interval (commonly 15 s) and records the values with the scrape timestamp. Push: the app (or an OpenTelemetry Collector) sends samples to the store. Pull makes "is the target alive?" trivial (up metric); push suits short-lived jobs.

Writing: memory, WAL, blocks

  1. New samples go into the in-memory head block (fast, recent data).
  2. They are also appended to a write-ahead log (WAL) on disk so a crash doesn't lose them.
  3. Every ~2 hours the head is compacted into an immutable, compressed block on disk with its own index. Older blocks are merged into bigger ones.
  4. Retention deletes blocks older than a limit (Prometheus defaults to 15 days). Long-term systems (Thanos, Mimir) ship blocks to object storage and may downsample (keep one point per 5 min instead of per 15 s).

To find series fast, the index is an inverted index: for each label pair (e.g. method="GET") it keeps a list of the series IDs that have it. A query for {method="GET",status="500"} intersects the two lists.

Compression: why it is so small

A naive sample is a 64-bit timestamp + 64-bit float = 16 bytes. Facebook's Gorilla paper (the basis for Prometheus-style compression) showed an average of about 1.37 bytes per sample on their data, using two observations:

  • Timestamps are regular. Scrapes happen at a fixed interval, so store the delta (difference from the previous timestamp), then the delta of the delta. When the interval is perfect, that is 0 — encoded in a single bit.
  • Values change slowly. XOR a value with the previous one; if they are identical, the result is all zeros and costs about one bit.

Show answer

1) Deltas: 60, 60, 61, 60. 2) Delta-of-delta: 0, 1, −1. 3) Only a delta-of-delta of 0 is a perfect one-bit sample. Here the scrape was 1 s late once (181 instead of 180), costing two small non-zero numbers. Jitter is cheap; a small non-zero value fits in a few bits, not 64.

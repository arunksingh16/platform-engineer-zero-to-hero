5 lessons, about 25 minutes each

Code analysis from zero

Build caches, test runners, sandboxes and linters all have to answer the same question before they can do their job: what does this code actually do? Learn how they work it out — and how to tell whether the answer is any good.

How each lesson works

  1. Idea in plain words with a tiny example.
  2. Play with an animation or interactive widget.
  3. Do it by hand — a short exercise with a hidden answer.
  4. Quiz — pass it to complete the lesson.

Lessons

    The problem at the end

    The course builds towards one real situation. A platform team cannot cache their CI because nobody knows which build steps touch the outside world. An engineer reports back: "trained a language-model classifier to identify if a function performs IO, 80% accuracy."

    By lesson 5 you can say what is missing from that sentence, build the simple thing it should have been measured against, and work out where a model actually earns its place. The code is in solution/ — standard library Python you can run against your own repository.

    Where this takes you

    These ideas sit underneath tools you already use: why Bazel insists on declaring every input, why your flakiest test is usually the one that writes to disk, how a linter knows you forgot to await, and how a sandbox policy gets written without guesswork.

    Progress is stored only in your browser. No tracking, no dependencies.

Lesson 12

Design a streaming platform

Turn the vocabulary into a reviewable design. The goal is not the most boxes: it is a path whose capacity, trust boundaries and failure behavior you can explain.

Your design brief

Serve 100,000 concurrent 160 kbit/s listeners, 2,400 API requests/s at peak and private playlists. Survive one zone failure without waiting for new VMs. Prepare for a second region, but do not claim regional recovery until data replication and failover are tested.

Separate delivery and control

Media: listener -> HTTP edge/cache -> protected media origin
APIs:  listener -> regional HTTP entry -> private API VMs -> private data
Ops:   trusted admin path -> management endpoints (not public SSH)
DNS:   public names + private zones/forwarding for internal dependencies

State assumptions: media is cacheable only under its access policy; private playlist responses bypass shared caches. API VMs are stateless or reconstruct state safely. Use TLS to clients and authenticated TLS to backends where required. Probes verify readiness without making one shared dependency eject every instance.

VMs in AWS/Azure can use the managed services directly: Kubernetes is not required. For private APIs used only from corporate networks, replace the public regional entry with an internal one and provide private client connectivity. Do not add NLB in front of ALB, or Front Door in front of Application Gateway, without a specific requirement justifying each hop.

Numbers that must survive review

  • Media: 16 Gbit/s payload; at 95% byte hits, approximately 0.8 Gbit/s origin payload in steady state. Test cold-cache and popular-release bursts.
  • API: at 500 requests/s measured safe capacity per VM, at least three VMs per zone across three zones give 3,000 requests/s after losing one zone. Add margin for actual bottlenecks.
  • Recovery: include probe detection, steering, reconnect and data recovery in the recovery-time objective. Define acceptable data loss as a separate recovery-point objective.
  • Cost: estimate CDN delivery, misses, LB processing, NAT, transfer and telemetry using measured byte and connection volumes.

Run the design review

Write down the owner and evidence for each: DNS failover, certificate rotation, origin bypass protection, zone capacity, draining a long-lived stream, egress exhaustion and regional data recovery. Then choose one failure to inject in a safe test environment.

Show a sample acceptance test

At representative peak API load, remove all targets in one test zone. Confirm the surviving fleet meets the declared latency/error SLO, no new traffic reaches drained targets after the expected window, and client retries remain within budget. Separately test a proxy failure and a cold-cache burst. Record detection time and interruption duration; a healthy dashboard without client measurements is insufficient.

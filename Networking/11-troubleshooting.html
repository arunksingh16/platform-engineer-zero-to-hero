Small, scoped probes

These are optional examples for systems you are authorized to test, using tools installed separately. api.music.example is a placeholder, not a working service.

dig api.music.example A
dig api.music.example AAAA
curl --connect-timeout 3 --max-time 10 -sS -o /dev/null \
  -w 'dns=%{time_namelookup} connect=%{time_connect} tls=%{time_appconnect} first_byte=%{time_starttransfer} total=%{time_total}\n' \
  https://api.music.example/ready
openssl s_client -connect api.music.example:443 \
  -servername api.music.example -verify_hostname api.music.example \
  -verify_return_error < /dev/null
ss -lnt
ip route get 10.20.1.11

ss and ip examples are Linux-specific. curl timing fields above are cumulative from request start, not separate hop durations. Subtract connect from TLS time to approximate the TLS phase for a new direct connection. Proxies and reuse change interpretation.

Use curl --resolve for an authorized known-IP test that preserves hostname/SNI; connecting to an IP URL changes those variables. ICMP ping success does not prove TCP port access, and ping failure does not prove the application is unreachable.

Cloud and VM evidence

AWS: inspect target health/reason codes, CloudWatch LB metrics, access logs, VPC Flow Logs and Reachability Analyzer for supported paths. Azure: inspect backend health, Azure Monitor metrics, access logs, Network Watcher connection troubleshooting and virtual network flow logs. Use current VNet flow logging guidance rather than building new tooling around legacy NSG flow logs.

On VMs, correlate proxy access/error logs with host sockets, interface drops and a narrowly scoped, authorized packet capture. Flow logs describe network metadata, not request payloads or proof of application success. Configuration analyzers do not replace live tests. Protect captures and logs: credentials and personal information can be present.

Incident drill

Small health responses work; large media responses stall only over a new VPN. CPU is normal. What do you test first?

Show answer

Suspect MTU/MSS and Path MTU Discovery along the tunnel. Compare packet sizes and retransmissions on both sides, check tunnel overhead and required ICMP signaling. Also rule out proxy/range/timeouts with evidence. Do not globally disable firewalls or randomly lower MTU everywhere.

Primary reading: Reachability Analyzer, Azure connection troubleshoot, VNet flow logs.

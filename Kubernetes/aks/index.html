AKS: production operations

Azure runs the control plane. You still own the outcome. Learn to reason across Kubernetes and Azure when a Pod cannot schedule, an identity cannot authenticate, or an upgrade cannot drain a node.

The operating mindset

For every design, name the owner, the failure domain, the capacity limit, the evidence you would collect and the recovery path. A green resource in the portal is not proof that a customer request succeeds.

Before you start

Complete Kubernetes fundamentals, especially scheduling, resource requests and autoscaling. The CNI track explains the packet model; Observability supplies the language of SLIs and SLOs. This track adds the Azure-specific operational contract rather than teaching Pods again.

Lessons

    How to use this track

    Each lesson pairs a mental model with inspection commands, a failure scenario, a worked exercise and a quiz. Commands use Azure CLI and kubectl, not an interactive Azure subscription connection from this website. Replace example names and check az account show and kubectl config current-context before using them. You need read access to the relevant Azure resources and Kubernetes objects; cluster-wide inspection may require a platform operator.

    No cluster creation required

    The written exercises and IP calculator work without Azure. Inspection commands require your own authorized environment; they do not provision resources. The identity YAML is a configuration fragment to review, not a complete deployable application. Never experiment on production without approval.

    Scope: AKS Standard is the baseline. Automatic, node autoprovisioning, networking migrations and add-ons have different controls and availability. Follow the linked primary documentation for your region, version, OS and service mode. No fixed Kubernetes minor version is assumed.

    What “production-ready” means here

    You can explain the identity chain, calculate upgrade headroom, predict scheduling constraints, trace a request and restore data against a measured recovery objective. These lessons are a foundation for a platform-specific runbook, not a certification that an arbitrary cluster is safe.

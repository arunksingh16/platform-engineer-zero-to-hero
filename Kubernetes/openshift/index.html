OpenShift for senior SREs

You already know Kubernetes. OpenShift is not Kubernetes plus a console — it is a platform in which almost everything, including the control plane, the operating system and the upgrade, is itself a set of operators reconciling toward a declared state. That changes where you look when something breaks, what you are allowed to touch, and how a bad change spreads.

How each lesson works

  1. Idea in plain words, assuming you have run production clusters.
  2. Play with a small interactive model where one helps.
  3. Do it by hand — an incident-shaped exercise with a hidden answer.
  4. Quiz — pass it to complete the lesson.

Lessons

    Who this is written for

    An engineer with several years of Kubernetes on-call behind them who is about to own OpenShift clusters at scale. It does not re-teach Pods, Services or RBAC. It teaches what is different, what is managed for you and therefore off-limits, and the failure modes that only exist on this platform: a degraded ClusterOperator, a paused MachineConfigPool, an SCC that admits the wrong workload, a Route that times out at exactly thirty seconds.

    Version note: written against OpenShift 4.x documentation current in November 2026. Defaults and feature stages move between minor releases. Where a behaviour is version-sensitive it is flagged — verify it against the release you actually run.

    What you will be able to do

    Explain which operator owns any given piece of the platform and read its status to find the real fault. Choose an installation topology and know which choices are permanent. Roll node configuration and cluster updates through production without taking down quorum or stranding a pool. Reason about SCCs, OAuth and RBAC well enough to review a tenant's access request. Trace traffic through OVN-Kubernetes and the HAProxy router. Pick storage for etcd, databases and shared files and know how each one fails. Design multi-tenancy with honest limits, take and restore an etcd backup, and run an incident in a sensible order.

    Before you start

    Do the main Kubernetes course first, especially operators and custom resources — this whole sub-course is that lesson applied to an entire platform. The CNI sub-course helps for lessons 10 and 11, and the Observability course for lesson 14.

    Every claim is sourced at the end of lesson 15. Progress is stored only in your browser. No tracking, no dependencies.

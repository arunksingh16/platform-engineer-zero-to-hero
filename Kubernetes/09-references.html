Every number and quotation in this course came from primary documentation, and this page says which. If something here disagrees with your cluster, your cluster is right — these are defaults, and defaults get overridden and change between versions.

How to use this page

Check anything you plan to rely on. Each row names the claim, the source, and where relevant the exact field so you can confirm it against the version you actually run.

A warning about version drift

This course was written against documentation current in November 2026. Kubernetes ships roughly three releases a year, and defaults do move — the HPAScaleToZero gate in lesson 5 changed stage and default between v1.16 and v1.37, which is exactly the kind of change that quietly invalidates a tutorial.

Two habits protect you:

  • Pin the docs to your version. The Kubernetes site serves older releases; use the version selector rather than reading /latest when something matters.
  • Ask the cluster, not the internet. kubectl explain reads the schema from your own API server, so it is always right for you: 
    kubectl explain deployment.spec.strategy.rollingUpdate
kubectl explain hpa.spec.behavior.scaleDown
kubectl api-resources            # everything your cluster serves, CRDs included
kubectl version

What is not sourced above

Three kinds of statement in this course are judgement, not documentation, and should be read that way:

Recommendations — "often leave the CPU limit off", "set a memory request always". These are defensible positions with real counter-arguments, and lesson 3 gives the counter-argument alongside.
Typical failure stories — the slow service with a low CPU limit, the queue consumer invisible to CPU autoscaling. Common patterns, not measurements.
Worked numbers — every exercise is arithmetic on the documented formulas, not data from a real cluster.
